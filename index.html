Quarto Termo: Reestruturação e Validação do Software

Reestruturação do Ambiente

Nos semestres anteriores, o Aether foi desenvolvido com o auxílio da plataforma Lovable, mas nunca chegou a ser usado na rotina de um cliente real. Nesse intervalo, o banco de dados hospedado no Supabase foi pausado por inatividade, o que causou falhas de autenticação. Por isso, a equipe retirou o código da plataforma e montou uma estrutura própria: um novo projeto no Supabase com acesso compartilhado entre os integrantes, o código versionado em um repositório no GitHub e a aplicação publicada no Vercel.

Após a publicação, o cadastro apresentou o erro Failed to fetch. A análise da aba Network do navegador mostrou que a aplicação ainda se comunicava com o projeto antigo por causa de um valor padrão gravado no código. A solução foi remover as credenciais do repositório e configurar as variáveis de ambiente no Vercel.

Nova Modelagem de Banco de Dados

O banco de dados foi reestruturado no novo projeto do Supabase. A modelagem passou a incluir as tabelas de autenticação e perfis (auth_users, profiles e user_roles), que sustentam o controle de acesso por perfil, além das tabelas de clientes, pedidos, produtos, matérias-primas, fichas técnicas, movimentações de estoque e itens do cardápio.

Diagrama entidade-relacionamento do AETHER no quarto semestre.

Análise do Código-Fonte e Problemas Identificados

O Aether é uma Single Page Application em React e TypeScript, sem API própria: o Supabase gera a API a partir das tabelas e o navegador a acessa diretamente. Com isso, a proteção dos dados depende das políticas de Row Level Security (RLS). Os problemas encontrados foram classificados por criticidade, combinando o impacto de uma eventual exploração com a facilidade de ela ocorrer, com base na norma ISO/IEC 25010.

Acesso do Cliente e Loja Virtual

Até o semestre anterior, o Aether atendia apenas quem opera o negócio. Nesta etapa foi implementado o perfil Clientes, que estende o acesso ao consumidor final da Bibi Brigadeiros. A Loja virtual apresenta o catálogo organizado por categorias, onde o cliente busca produtos, consulta preço e descrição e adiciona itens ao carrinho para fazer o pedido.

Tela da Loja do sistema.

O perfil dos usuários passou a ser armazenado em uma tabela específica, com acesso inicialmente pendente. Somente o Master altera permissões, por meio de uma Edge Function que verifica sua autorização, e as políticas de RLS foram revisadas para que cada cliente acesse apenas os dados permitidos.

Remodelagem de Banco de Dados

A estrutura do banco de dados do AETHER foi replanejada para garantir integridade e eficiência no gerenciamento das informações da confeitaria.

Diagrama Entidade-Relacionamento (DER) do sistema AETHER, apresentando a estrutura do banco de dados e a integração entre estoque, pedidos, produtos, usuários e fichas técnicas.

Automação de Produção e Estoque Inteligente

Foi desenvolvido um módulo de automação de produção baseado em Ficha Técnica, responsável por controlar insumos, custos e estoque dos produtos. Também foi criada a função “Produzir”, que automatiza a fabricação ao verificar a disponibilidade dos materiais, realizar a baixa das matérias-primas e atualizar automaticamente o estoque do produto final.

Fluxo automatizado do processo de produção e baixa de estoque.

Dashboard Analítico e Business Intelligence

O sistema passou a incorporar funcionalidades de BI, transformando dados operacionais em indicadores estratégicos para apoio à tomada de decisões. O dashboard desenvolvido permite acompanhar métricas como margem de lucro, custos de produção, movimentação de estoque e desempenho de vendas.
